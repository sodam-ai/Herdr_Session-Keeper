## 1. 한눈에 보기

### 1.1 무엇인가요?

**Herdr**(허더)는 터미널(검은 명령 창)을 여러 개 한 화면에 모아 보여 주는 프로그램입니다. 터미널 안에서 **Claude Code**나 **Codex** 같은 AI 도우미와 대화하며 일하는 분이 많습니다.

문제는 이럴 때 생깁니다.

- 컴퓨터를 껐다 켜면 Herdr 의 창은 **빈 터미널로 돌아오고**, 하던 AI 대화는 끝나 있습니다. (대화 **기록**은 파일로 남아 있지만, 어느 창에서 어느 대화를 하고 있었는지는 사람이 기억해야 합니다.)
- Herdr 를 계속 켜 둔 채로는 **앱 업데이트가 영영 적용되지 않습니다.** (원인과 해결은 [11. 업데이트 내용 요약](#11-업데이트-내용-요약)에 있습니다.)

**세션키퍼**는 이 두 가지를 해결합니다.

| 기능 | 쉽게 말하면 | 자동/수동 |
|---|---|---|
| 세션 기억 | 1분마다 "어느 창에서 어느 AI 대화를 하는지"를 메모해 둡니다. | 자동 |
| 세션 복구 | Herdr 를 다시 켜면 메모를 보고 `claude --resume <대화번호>` 또는 `codex resume <대화번호>` 를 그 창에 입력해 대화를 이어 줍니다. | 자동 + 수동(버튼) |
| 세션키퍼 창 | Herdr 안에서 `Ctrl+Shift+R` 을 누르면 열리는 목록 창. 복구할 대화를 눈으로 보고 골라 복구합니다. | 수동 |
| 앱 자동 업데이트 | Herdr 가 열려 있어도 새 버전을 안전하게 적용합니다. 실패하면 전부 원래대로 되돌립니다. 끄고 켤 수 있습니다. | 자동(끌 수 있음) + 수동 |

### 1.2 하지 않는 일 (오해 방지)

- 인터넷으로 **아무것도 보내거나 받지 않습니다.** 이 도구의 코드에는 인터넷 접속 부분이 없습니다([15장](#15-보안과-데이터-흐름) 참고).
- AI 대화의 **내용**을 복원하지는 않습니다. 대화 **기록 파일**을 이어서 여는 것입니다. 컴퓨터가 꺼질 때 AI 가 하던 "한 번의 작업"은 이어지지 않습니다.
- AI 세션 안에서 켜 둔 **감시(Monitor)·예약(ScheduleWakeup/Cron)** 은 되살리지 않습니다(알려 주기만 합니다).
- 컴퓨터를 **저절로 켜 주지 않습니다.** 부팅만으로는 아무것도 켜지지 않고, 사용자가 Herdr 를 켜야 동작합니다.
- 직접 닫은 창은 되살리지 않습니다(사고로 닫힌 창만 대상입니다).

### 1.3 누구에게 필요한가요?

Windows 에서 Herdr 를 쓰면서 Claude Code 또는 Codex 로 여러 작업을 동시에 하는 분. 한두 개 창만 쓴다면 필요성이 낮습니다.

## 2. 용어 풀이

| 용어 | 뜻 (쉬운 설명) |
|---|---|
| 터미널 | 글자로 명령을 입력하는 검은(또는 흰) 창. 이 문서에서는 "창"이라고도 부릅니다. |
| Herdr (허더) | 터미널 여러 개를 공간·탭으로 정리해서 보여 주는 앱. 앱 프로그램은 `herdr-app`, 터미널을 실제로 붙잡고 있는 뒷일꾼은 `herdr-core`(명령 도구 이름 `hc`)입니다. 앱 창을 닫아도 `herdr-core` 가 터미널을 살려 둡니다. |
| 세션 (AI 세션) | Claude Code 나 Codex 와 나눈 "대화 하나". 대화마다 번호(ID)가 있습니다. |
| 세션 ID / resume ID | 대화 하나를 가리키는 긴 번호(예: `12345678-7110-…`). 이 번호로 대화를 이어 엽니다. |
| Claude Code | Anthropic 사의 AI 코딩 도우미(터미널용). 이어 열기 명령은 `claude --resume <번호>`. |
| Codex | OpenAI 의 AI 코딩 도우미(터미널용). 이어 열기 명령은 `codex resume <번호>`. |
| 세션키퍼 | 이 프로젝트의 이름. 두 부분으로 되어 있습니다: ① Herdr 안의 **세션키퍼 창**(목록) ② 뒤에서 도는 **키퍼 프로그램**(`session-keeper.ps1`). |
| 모드 (Herdr 모드) | Herdr 에 끼워 넣는 작은 추가 기능 폴더. 세션키퍼 창이 이것입니다. |
| PowerShell | Windows 에 기본으로 들어 있는 명령 도구. 이 도구의 본체 스크립트(`.ps1`)가 이걸로 돕니다. |
| Node.js | 자바스크립트 프로그램을 실행해 주는 프로그램. 목록·복구 도구(`.mjs`)가 이걸로 돕니다. 따로 설치해야 합니다. |
| 작업 스케줄러 | Windows 가 정해진 시각마다 프로그램을 실행해 주는 기능. 세션키퍼는 1분마다 "Herdr 가 켜져 있나?" 확인하는 아주 짧은 작업을 여기에 등록합니다. |
| 마켓플레이스 / 플러그인 | **Claude Code** 의 확장 기능 설치 방식(앱 스토어와 비슷). 이 프로젝트는 Claude Code 용 마켓플레이스 형태로도 제공됩니다. **Herdr 에는 이런 설치소가 없습니다.** |
| 경로 | 파일이 있는 위치 주소. 예: `C:\Users\내이름\Documents`. |
| 관리자 권한 | 컴퓨터 전체를 바꿀 수 있는 높은 권한. **이 도구는 필요 없습니다.** |
| 백업 | 바꾸기 전에 원본을 따로 복사해 두는 것. 문제가 생기면 되돌릴 수 있습니다. |
| 로그 | 프로그램이 "무엇을 했는지" 적어 둔 기록 파일. |
| 토글(▶) | 이 문서에서 클릭하면 펼쳐지는 접이식 항목(웹 브라우저·GitHub 에서 보입니다). |

## 3. 사전 준비물과 필요 프로그램

### 3.1 반드시 필요한 것

| 필요한 것 | 왜 필요한가 | 확인 방법 | 없으면 |
|---|---|---|---|
| Windows 10/11 (64비트) | 이 도구는 Windows 전용입니다. | 개발·시험은 **Windows 11 Home 10.0.26300** 에서만 했습니다. Windows 10 은 **미확인**입니다. | 다른 OS 는 지원하지 않습니다. |
| Windows PowerShell 5.1 | 본체 스크립트 실행 | Windows 에 기본 포함. 시험 버전 5.1 | 보통 이미 있습니다. |
| **Herdr** (앱 + 코어) | 이 도구가 관리하는 대상 | 시험 버전: herdr-app **0.1.14 → 0.1.15**, herdr-core/hc **0.1.20** | [4.1](#41-herdr-받기) |
| **Node.js 18 이상** | 목록·복구 도구 실행 | 터미널에 `node --version` 입력. 시험 버전 v26.7.0 | [4.2](#42-nodejs-받기) |
| 쓸 수 있는 폴더 | 설치 위치(기본 `%LOCALAPPDATA%\HerdrSessionKeeper\app`) | 보통 가능 | 다른 위치를 `-InstallDir` 로 지정 |

### 3.2 있으면 좋은 것 (선택)

| 선택 프로그램 | 용도 |
|---|---|
| Claude Code | Claude 대화를 복구하려면 필요(복구는 `claude --resume` 을 실행). |
| Codex CLI | Codex 대화를 복구하려면 필요(`codex resume`). |
| Claude Code 의 플러그인 기능 | "마켓플레이스 설치"([5.1](#51-방법-1--claude-code-마켓플레이스로-설치))를 쓸 때만 필요. 없어도 [5.2](#52-방법-2--직접-설치-더블클릭) 로 설치할 수 있습니다. |

### 3.3 설치 전에 정해 두면 좋은 것

- 설치 위치를 바꾸고 싶은지(기본값이면 아무것도 안 해도 됩니다).
- 자동 업데이트를 켜 둘지(기본 **켜짐**). 나중에 언제든 바꿀 수 있습니다.
- 작업 스케줄러 등록을 허용할지(허용하지 않으면 Herdr 를 켜도 키퍼가 저절로 켜지지 않아 수동 실행이 필요합니다. 옵션 `-NoTask`).

### 3.4 권한

- **관리자 권한이 필요 없습니다.** 현재 로그인한 사용자 계정에만 설치됩니다.
- 회사 PC 처럼 작업 스케줄러 등록이나 스크립트 실행이 제한된 환경에서는 설치 중 경고가 나올 수 있습니다([16장](#16-문제오류-대처-방법)).

## 4. 다운로드 방법

> **현재 상태(2026-11-11)**: 이 꾸러미는 GitHub 저장소 <https://github.com/sodam-ai/Herdr_Session-Keeper> 에 공개되어 있습니다. 아래 4.3 의 방법으로 받으세요.

### 4.1 Herdr 받기

- Herdr 공식 저장소: <https://github.com/herdrdev/herdr> — 설치 방법은 그곳의 안내를 따르세요.
- 설치 뒤 **한 번 실행**해 두세요(설정 폴더 `%USERPROFILE%\.config\herdr-app` 가 만들어져야 세션키퍼를 설치할 수 있습니다).
- 확인: 시작 메뉴에서 Herdr 를 열 수 있고, 일반 위치에 설치했다면 `%LOCALAPPDATA%\Programs\herdr-app\herdr-app.exe` 파일이 있습니다.

### 4.2 Node.js 받기

1. 웹 브라우저로 <https://nodejs.org> 에 갑니다.
2. **LTS** 라고 적힌 설치 파일을 받아 실행하고, 안내대로 "다음"을 눌러 끝까지 설치합니다.
3. **새 터미널**을 열고 `node --version` 을 입력해 `v18` 이상 숫자가 나오는지 확인합니다. (설치 직후 열려 있던 터미널은 새 설치를 모를 수 있어 **새로 열어야** 합니다.)
4. 참고: `winget`(Windows 패키지 관리자)이 있는 PC 라면 그것으로도 설치할 수 있다고 알려져 있으나, **개발 PC 에는 winget 이 없어 확인하지 못했습니다.**

### 4.3 세션키퍼 꾸러미 받기

저장소 최상위에 `.claude-plugin`(마켓플레이스 목록)과 `plugins\herdr-session-keeper`(설치 꾸러미)가 들어 있습니다. 설치 프로그램은 `plugins\herdr-session-keeper\install.cmd` 입니다.

1. 저장소 페이지의 초록색 **Code** 버튼 → **Download ZIP** 으로 받거나, git 이 있다면 `git clone https://github.com/sodam-ai/Herdr_Session-Keeper.git` 을 실행합니다.
2. 받은 폴더(또는 ZIP 파일)를 설치할 PC 에 옮깁니다(같은 PC 에서 받았다면 건너뜁니다).
3. 설치할 PC 에서 **압축을 완전히 풉니다.** (압축 파일 안에서 바로 실행하면 안 됩니다. `payload` 폴더를 찾지 못해 "설치 파일이 없습니다" 로 멈춥니다.)
4. 폴더 경로에 한글·공백이 있어도 동작하도록 시험했지만, 가능하면 영문 경로를 권장합니다.

설치 꾸러미를 직접 다시 만들려면(개발자용): 프로젝트 폴더에서 `node build-kit.mjs` ([10.7](#107-빌드시험배포-방법-개발자용) 참고).

## 5. 설치 방법

설치 방법은 두 가지입니다. **방법 2(더블클릭)가 가장 쉽습니다.**

먼저 어느 방법이든 **점검만** 해 볼 수 있습니다. 점검은 아무것도 바꾸지 않습니다([5.3](#53-설치-전-점검-추천)).

### 5.1 방법 1 — Claude Code 마켓플레이스로 설치

Claude Code 에서 아래 두 줄을 한 줄씩 입력합니다. 이 저장소가 그대로 마켓플레이스입니다.

```
/plugin marketplace add sodam-ai/Herdr_Session-Keeper
/plugin install herdr-session-keeper@herdr-session-keeper-market
```

그다음 Claude 에게 **"세션키퍼 설치해줘"** 라고 말하면, 들어 있는 스킬이 **점검 → 바뀌는 내용 설명 → 확인 → 설치** 순서로 진행합니다.

> **미확인**: 이 두 명령을 실제 Claude Code 에서 끝까지 실행해 본 적은 없습니다. 꾸러미 형식 검사(`claude plugin validate`)만 통과했습니다. 문제가 있으면 방법 2 를 쓰세요.

### 5.2 방법 2 — 직접 설치 (더블클릭)

1. 꾸러미 폴더 안 `plugins\herdr-session-keeper\install.cmd` 를 **더블클릭**합니다.
2. 검은 창에 진행 상황이 나옵니다(6단계). 끝나면 "설치가 끝났습니다."가 나옵니다.
3. 아무 키나 눌러 창을 닫습니다.

터미널에서 직접 실행하려면:

```
powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-session-keeper\install.ps1
```

### 5.3 설치 전 점검 (추천)

```
powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-session-keeper\install.ps1 -Check
```

Node.js·Herdr·설정 폴더·다른 위치의 기존 설치를 확인만 하고 끝납니다. "점검 완료: 설치할 수 있는 환경입니다"가 나오면 준비가 된 것입니다. "중단:" 으로 시작하는 줄이 나오면 그 이유를 해결한 뒤 다시 하세요.

### 5.4 설치가 하는 일 (6단계)

| 단계 | 하는 일 |
|---|---|
| 1/6 환경 점검 | Node.js 18+, Herdr 앱, `hc`, Herdr 설정 폴더를 찾습니다. 다른 위치에 이미 설치된 세션키퍼가 있는지 봅니다. |
| 2/6 프로그램 복사 | 프로그램 파일을 설치 위치로 복사하고(이전 설치가 있으면 한 벌 백업, 최근 3벌 보관), 찾은 위치들을 `kit.env` 에 적습니다. |
| 3/6 Herdr 모드 | `mods\session-keeper` 에 화면 파일 3개를 복사하고 설치 위치·node 경로를 채워 넣은 뒤 Herdr 공식 검사(`herdr-app check`)를 돌립니다. |
| 4/6 키 연결 | `keys.json` 에 `Ctrl+Shift+R` 한 줄을 추가합니다(원본 백업 `keys.json.bak-before-session-keeper-kit`, 추가 후 JSON 이 깨지면 원래대로). |
| 5/6 자동 실행 작업 | 작업 스케줄러에 `HerdrSessionKeeper-Watchdog` 를 만듭니다(1분마다, Herdr 가 켜져 있을 때만 키퍼를 켬). |
| 6/6 마무리 | 설치 기록(`kit.install.json`)을 쓰고, Herdr 가 켜져 있으면 감시를 즉시 한 번 호출합니다. |

### 5.5 설치 옵션

| 옵션 | 의미 |
|---|---|
| `-Check` | 점검만 하고 아무것도 바꾸지 않음 |
| `-InstallDir <경로>` | 프로그램 설치 위치(기본 `%LOCALAPPDATA%\HerdrSessionKeeper\app`) |
| `-HerdrHome <경로>` | Herdr 설정 폴더(기본: 환경변수 `HERDR_APP_HOME`, 없으면 `%USERPROFILE%\.config\herdr-app`) |
| `-HerdrApp <경로>` | `herdr-app.exe` 위치(자동 탐색이 실패할 때) |
| `-TaskName <이름>` | 작업 스케줄러 작업 이름(기본 `HerdrSessionKeeper-Watchdog`) |
| `-NoTask` | 작업 스케줄러 등록 안 함 |
| `-NoKey` | `Ctrl+Shift+R` 연결 안 함(대신 `Ctrl+Shift+P` → `mod.open session-keeper`) |
| `-Launcher` | (선택) Herdr 바로가기를 런처에 연결([8.5](#85-앱-자동-업데이트-쓰는-법)) |
| `-RestartKeeper` | 이미 돌고 있는 키퍼를 끄고 새 코드로 다시 시작(1분 안에 감시가 다시 켬) |
| `-Force` | **다른 위치**에 설치된 기존 세션키퍼를 이 설치로 교체 |

### 5.6 이미 세션키퍼가 설치되어 있다면

다른 위치에 설치된 작업(작업 스케줄러)이나 모드가 있으면 설치는 **덮어쓰지 않고 멈춥니다**("중단: … 덮어쓰지 않았습니다"). 기존 것을 계속 쓰거나, 이 설치로 바꾸려면 `-Force` 를 붙이세요(기존 작업·모드가 이 설치를 가리키도록 바뀝니다). 같은 위치에 다시 설치(업데이트)하는 것은 그냥 됩니다.

### 5.7 환경·폴더·컴퓨터가 달라도 동작하는 방법

설치할 때 그 PC 에서 아래 위치를 **자동으로 찾아** `kit.env` 에 적어 둡니다(경로가 코드에 박혀 있지 않습니다).

| 찾는 것 | 순서 |
|---|---|
| Node.js | PATH → `%ProgramFiles%\nodejs` 등 흔한 위치 (18 이상만 인정) |
| Herdr 앱 | `-HerdrApp` → 환경변수 `KEEPER_APP_EXE` → `%LOCALAPPDATA%\Programs\herdr-app` → PATH → 설치 목록(레지스트리) |
| hc (herdr-core) | PATH → 앱 옆 `herdr-core` → `%LOCALAPPDATA%\Programs\herdr-core` |
| Herdr 설정 폴더 | `-HerdrHome` → 환경변수 `HERDR_APP_HOME` → `%USERPROFILE%\.config\herdr-app` |
| Claude 설정 폴더 | 환경변수 `CLAUDE_CONFIG_DIR` → `%APPDATA%\claude-code`(있을 때) → `%USERPROFILE%\.claude` |
| Codex 데이터 | 환경변수 `CODEX_HOME`, `%USERPROFILE%\.codex`, `%USERPROFILE%\.codex_runtime`(있는 것 모두) |

폴더를 옮기려면 새 위치에 `-InstallDir 새위치` 로 다시 설치하고, 옛 위치는 `uninstall.ps1 -InstallDir 옛위치` 로 지우세요.

## 6. 빠른 시작 (10분)

처음이라면 이 순서만 따라 하세요.

1. **Node.js 설치**([4.2](#42-nodejs-받기)) 후 새 터미널에서 `node --version` 확인.
2. **Herdr 설치** 후 한 번 실행([4.1](#41-herdr-받기)).
3. **꾸러미 폴더를 옮기고 압축을 풉니다**([4.3](#43-세션키퍼-꾸러미-받기)).
4. `plugins\herdr-session-keeper\install.cmd` 를 **더블클릭**(점검부터 보고 싶으면 [5.3](#53-설치-전-점검-추천)).
5. "설치가 끝났습니다." 확인.
6. **Herdr 화면에서 `Ctrl+Shift+R`** 을 눌러 세션키퍼 창이 열리는지 확인합니다. 안 열리면 `Ctrl+Shift+P` 를 누르고 `mod.open session-keeper` 를 입력합니다.
7. Herdr 가 켜져 있으면 **약 1분 안에** 키퍼가 저절로 켜집니다(확인: 설치 폴더의 `session-keeper.alive` 파일이 생기고 1분마다 갱신됨).
8. 평소처럼 Claude Code / Codex 로 일하세요. 이제부터 세션키퍼가 1분마다 기억합니다.
9. (나중에) 컴퓨터를 껐다 켜거나 Herdr 가 닫혔다면 **Herdr 를 다시 실행**하세요. 몇 분 안에 자동 복구가 진행되고, 끝나면 알림이 뜹니다. 안 된 창은 `Ctrl+Shift+R` 목록에서 **[복구]** 를 누릅니다.

## 7. 실행 방법 (켜기·끄기)

### 7.1 평소에는 아무것도 안 해도 됩니다

- 작업 스케줄러가 1분마다 "Herdr 가 켜져 있나?"를 봅니다.
  - Herdr 꺼짐 → 아무것도 안 함.
  - Herdr 켜짐 + 키퍼 살아 있음(`session-keeper.alive` 가 3분 안에 갱신) → 아무것도 안 함.
  - Herdr 켜짐 + 키퍼 없음 → 키퍼를 켬(Herdr 를 켠 뒤 최대 약 1분).
- 키퍼는 Herdr 가 **2분 넘게 꺼져 있으면 스스로 종료**합니다. **PC 부팅만으로는 아무것도 켜지지 않습니다.**

### 7.2 수동으로 켜기

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<설치 위치>\session-keeper.ps1" -Mode Run
```

(`<설치 위치>` 기본값: `%LOCALAPPDATA%\HerdrSessionKeeper\app`. 같은 키퍼가 이미 돌고 있으면 새로 뜬 쪽이 조용히 끝납니다.)

### 7.3 끄기

| 하고 싶은 것 | 방법 |
|---|---|
| 자동 실행만 끄기 | `schtasks /Delete /TN "HerdrSessionKeeper-Watchdog" /F` (또는 제거 도구, [20장](#20-제거와-되돌리기)) |
| 지금 돌고 있는 키퍼 멈추기 | 작업 관리자에서 `session-keeper` 가 든 `powershell.exe` 종료 |
| 앱 자동 업데이트만 끄기 | `session-keeper.ps1 -Mode Update -Auto Off` ([8.5](#85-앱-자동-업데이트-쓰는-법)) |

## 8. 사용 방법

### 8.1 세션키퍼 창 열기

Herdr 안에서 `Ctrl+Shift+R`. 다시 누르거나 `Esc` 를 누르면 닫힙니다. 안 열리면 `Ctrl+Shift+P` → `mod.open session-keeper`.

### 8.2 화면 구성

맨 윗줄: 제목 · 탭 3개 · 검색창 · **[새로고침]** / 둘째 줄: 탭별 도구 / 목록 / 맨 아래: 상태·단축키 안내. 20초마다 자동 새로고침됩니다(전부 복구 중에는 5초).

| 탭 | 보여 주는 것 | 단축키 |
|---|---|---|
| **복구 대기** | 닫히거나 꺼져서 복구를 기다리는 작업(Herdr 의 공간/탭 이름으로 묶음). 복구할 게 있으면 이 탭이 먼저 열리고 빨간 점이 뜹니다. | `Ctrl+1` |
| **열려 있는 창** | 지금 Herdr 에 떠 있는 AI 창(공간별). 위쪽 상태 칩(승인 대기·작업 중·끝남·대기)을 누르면 그 상태만 보입니다. | `Ctrl+2` |
| **꺼진 세션** | 자동 복구 대상이 아닌 지난 Claude/Codex 대화(폴더별). AI 종류로 거를 수 있습니다. | `Ctrl+3` |

검색창에서 `Enter` 를 누르면 첫 결과를 실행합니다(복구 대기·꺼진 세션은 복구, 열린 창은 이동).

### 8.3 복구 대기 탭 — 버튼

| 버튼 | 하는 일 | 주의 |
|---|---|---|
| **[전부 복구 (N)]** | 복구 대기 작업 전부를 키퍼가 복구(백그라운드, 몇 분). 진행 중 "남은 N개 / M개" 표시 | **한 번 더 눌러야 실행** |
| **[미리보기]** | 입력·생성 없이 항목마다 "빈 창에 이어서 입력 / 새 탭으로 열기 / 건너뜀 — 이유"만 보여 줌 | 안전(아무것도 안 바꿈) |
| **[복구]** | 그 한 항목만 복구 | |
| **[목록에서 제외]** | 영영 끝낸 작업을 복구 목록에서 뺌(대화 기록 파일은 안 지움) | 한 번 더 눌러야 실행 |
| **[옛 항목 N개 제외]** | "직접 복구" 로 분류된 옛 항목을 한꺼번에 뺌(뺄 때 백업 파일을 먼저 만듦) | 한 번 더 눌러야 실행 |

항목 상태: `복구 대기`(자동 복구 대상) · `직접 복구`(옛 항목, 버튼으로만) · `자동 복구 실패`(자동 3번 시도 뒤 포기 → [복구]는 새 탭으로 이어서 시작) · `복구 불가`(대화 기록 파일이 사라짐 → 제외만 가능).

### 8.4 열려 있는 창·꺼진 세션 탭 — 버튼

| 버튼 | 하는 일 |
|---|---|
| **[이 창으로 이동]** | 화면만 그 창으로 옮깁니다(입력·종료 없음). |
| **[복구]** (꺼진 세션) | 새 탭을 열어 `claude --resume` / `codex resume` 으로 이어서 시작합니다. 이미 어딘가에서 실행 중인 대화는 **같은 대화에 창 두 개가 쓰는 사고**를 막기 위해 열지 않습니다. |
| **[ID 복사]** | 앞 8자리 칩을 누르면 **전체 ID** 가 복사됩니다. |
| **[명령 복사]** (마우스를 올릴 때) | `claude --resume <ID>` 또는 `codex resume <ID>` 한 줄이 복사됩니다. 터미널에 붙여 넣으면 이어집니다. |

`ID 확인 불가` 로 표시된 창은 눌러서 이유를 볼 수 있습니다(예: 같은 폴더에 Codex 창이 둘 이상이라 하나로 정할 수 없음).

### 8.5 앱 자동 업데이트 쓰는 법

세션키퍼 창 위쪽 한 줄에 업데이트 상태가 나옵니다.

| 상태 | 뜻 |
|---|---|
| 받아 둔 새 버전 있음(`ready`) | Herdr 가 새 버전(예: 0.1.15)을 받아 두었지만 아직 적용 전 |
| 창 재시작 필요(`restart`) | 파일은 새 버전인데 창이 옛 버전으로 떠 있음 |
| 할 일 없음(`none`) | 최신 |

| 버튼 | 하는 일 |
|---|---|
| **[앱 업데이트]** | 파일을 안전하게 교체하고 Herdr **창만 껐다 켭니다**(터미널은 `herdr-core` 가 유지). **두 번 눌러야 실행.** 창이 잠깐 닫혔다 열립니다. |
| **[자동 업데이트: 켜짐/꺼짐]** | 자동 적용을 켜고 끕니다(기본 켜짐). 끄면 `session-keeper.appupdate.off` 파일이 생깁니다. |

> **두 버튼이 가까이 있으니 누를 때 화면을 확인하세요.** 개발 PC 에서 한 번, 업데이트와 "자동 업데이트 꺼짐"이 같은 초에 기록된 일이 있었습니다(원인 미확정, 버튼 위치 이동 가능성). 의도와 다르면 `-Mode Update -Auto On` 으로 다시 켜세요.

**자동 적용 시점**(자동 업데이트가 켜져 있을 때):

1. **Herdr 가 켜진 지 3분 이내**에 키퍼가 옛 버전을 발견하면 바로 적용합니다. 오래 켜 둔 창은 **저절로 껐다 켜지 않고** 알림만 합니다.
2. (선택) 런처를 설치했다면 **앱이 켜지기 전에** 적용합니다.
3. (선택) `session-keeper.appupdate.idle` 파일을 만들면 앱이 켜진 채 한가할 때도 적용합니다(기본 꺼짐).

**런처(선택)**: `session-keeper.ps1 -Mode Update -Launcher Install` — 바탕화면·시작 메뉴 바로가기를 런처에 연결하고 **시작 위치를 사용자 폴더로 고칩니다**(Herdr 설치 폴더가 시작 위치면 업데이트가 막히는 것이 근본 원인이기 때문, [11장](#11-업데이트-내용-요약)). 작업표시줄 고정 아이콘은 시작 위치만 고칩니다. 원본 바로가기는 `shortcut-backup\` 에 백업되며 `-Launcher Uninstall` 로 되돌립니다. 런처가 실패해도 Herdr 는 반드시 켜집니다. **실제 바로가기에 설치해 본 적은 없습니다(미확인, [19장](#19-검증-현황과-알려진-한계)).**

### 8.6 복구 결과 확인하기 (재부팅 뒤)

- 화면 알림: "Herdr 세션 복구 완료" 또는 "확인 필요".
- `LAST-RESTORE.txt` 맨 위 **판정** 줄(설치 폴더 안):

| 판정 | 뜻 |
|---|---|
| `정상` | 전부 복구됨(또는 이미 실행 중) |
| `주의` | 확인이 필요한 창이 있음 → 파일 아래 목록과 `다음 할 일` 확인. `주의 - 대화는 전부 복구됨 · 감시·예약 재가동 필요 N 개` 이면 대화는 돌아왔지만 그 창에서 켜 두었던 감시·예약은 **직접 다시 켜야** 합니다. |
| `복구할 것 없음` | 복구 대상이 없었음(평소 Herdr 만 다시 켠 경우) |
| `확인 필요 - 재부팅 직후인데 복구할 기록이 없습니다` | 기록이 비었을 수 있음 → `session-keeper.log` 확인 |

더 자세한 기록: `session-keeper.log`, 지난 결과들: `restore-history.log`.

## 9. 작동 방법 (어떤 원리로 동작하나)

### 9.1 평소 (1분마다): 기억하기

키퍼가 Herdr 코어(`hc ls`)에서 열린 창 목록을 읽고, 각 창에서 돌고 있는 AI 대화의 번호를 알아내 `session-map.json` 에 적습니다.

- **Claude**: Claude Code 가 남기는 실행 중 세션 파일과 **프로세스 계보**(세션 → 부모 … → 창의 셸)로 어느 창인지 정확히 연결합니다.
- **Codex**: 아래 순서로 확정합니다. 확실하지 않으면 **기록하지 않고** 이유를 로그에 남깁니다(틀린 대화를 이어 붙이는 것보다 낫기 때문).
  1. 명령줄의 `codex resume <ID>` (키퍼가 복구한 창은 전부 이 방식이라 정확).
  2. 같은 작업 폴더 + 창이 켜진 뒤 갱신된 대화 파일.
  3. 같은 폴더에 Codex 창이 둘 이상이면 **화면 대조**: 후보 대화의 최근 발화 앞 40자(공백 무시)가 어느 창 화면(`hc read`)에 보이는지 비교해, **창 하나가 후보 하나와만 맞고 그 후보도 다른 창과 겹치지 않을 때만** 확정.
- 같은 부팅 중에 사라진 창의 기록은 "사고(6개 이상 한꺼번에)"인지 "사용자가 직접 끝냄(1~2개)"인지 구분해, 사고면 **보존**하고 직접 끝낸 것은 2분 뒤 정리합니다.
- 직접 닫은 창은 로그에 `직접 닫은 창: … (다시 열려면 claude --resume <ID>)` 로 남고 복구 목록에서 빠집니다. 판정 조건: 같은 Herdr 가 계속 떠 있고(살아 있는 창 1개 이상) 그 창의 종료 기록이 `killed` 일 때만. 판단이 불확실하면 **사고로 보고 보존**합니다.

### 9.2 Herdr 를 다시 켰을 때: 복구하기

1. 키퍼가 켜지면 복구 시도를 시작합니다(10분 동안 30초 간격, 못 끝낸 항목이 있으면 최대 30분).
2. **자동 복구 대상**은 "닫히기 직전에 열려 있던 창"(마지막 확인 시각이 가장 늦은 것에서 10분 이내)만입니다. 더 옛 항목은 복구 목록에 `직접 복구` 로 남아 버튼으로만 복구됩니다.
3. 순서: `restore-priority.txt` 의 공간 이름 순(기본 `프로젝트`) → 같은 공간 안에선 최근에 쓴 것 먼저 → 창 주소. 6개씩 묶고 묶음 사이 4초.
4. 창 종류별 동작:
   - **빈 셸로 되살아난 창** → 그 셸에 `claude --resume <ID>` (또는 `codex resume <ID>`) 입력. 창 배치·이름 유지.
   - **끝나 버린 창** → 같은 이름의 공간에 **새 탭**을 만들어 실행(코어가 켜진 지 120초 뒤부터).
5. **안전 규칙 — 하나라도 어긋나면 그 창은 건너뜁니다**: 같은 대화가 이미 실행 중이 아님 / 대화 파일(`.jsonl`) 존재 / 시도 3회 미만 / (빈 셸) 같은 탭 + 앞 프로그램이 powershell + AI 없음 + 빈 프롬프트 / (새 탭) 코어 시작 120초 뒤.
6. 끝나면 `LAST-RESTORE.txt` 에 결과를 쓰고 알림을 한 번 띄웁니다.

### 9.3 Herdr 앱 업데이트가 안 되던 이유와 해결 (쉬운 설명)

- Herdr 는 새 버전을 `herdr-app.new` 폴더에 받아 두고, 껐다 켤 때 **설치 폴더의 이름을 바꿔서** 교체합니다.
- Windows 는 **"누군가 작업 위치로 쓰고 있는 폴더"의 이름을 바꾸지 못합니다.** 개발 PC 에서는 바로가기의 "시작 위치"가 설치 폴더라서 앱 1개 + 코어 4개 + 터미널 호스트 34개가 그 폴더를 붙잡고 있었습니다(실측). 그래서 교체가 영영 실패했습니다.
- 세션키퍼는 **폴더 이름이 아니라 폴더 안의 파일**을 바꿉니다(실행 중인 프로그램 파일도 이름은 바꿀 수 있기 때문).

| 단계 | 설명 |
|---|---|
| ① 전체 백업 | `herdr-app.backup-<버전>-<시각>` 폴더(최근 2개 보관) |
| ② 파일별 교체 | 옛 파일을 `.old-<시각>` 으로 이름 변경 → 새 파일 복사 |
| ③ 검증 | 모든 파일의 SHA256 과 `--version` 확인 |
| ④ 실패 시 | **전부 원복**(하나라도 틀리면) |
| ⑤ 창 재시작(선택) | 옛 창에 옛 프로그램으로 종료 신호(`app.quit`) → 새 프로그램으로 창 기동 → 살아 있는 터미널 수 비교 |
| 안전장치 | 업데이트가 창을 끈 뒤 멈추면 키퍼가 20초 뒤 대신 앱을 켭니다. 재시작 중에는 키퍼가 복구 창을 열지도, 기록을 지우지도 않습니다. |

## 10. 명령어 모음

모든 명령은 PowerShell/터미널에서 실행합니다. `<설치 위치>` 는 기본 `%LOCALAPPDATA%\HerdrSessionKeeper\app` 입니다. 따옴표는 경로에 공백이 있을 때 필요합니다.

### 10.1 키퍼 (`session-keeper.ps1`)

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<설치 위치>\session-keeper.ps1" -Mode <모드> [옵션]
```

| 모드 | 하는 일 |
|---|---|
| `Snapshot` (기본) | 지금 상태를 한 번 기록 |
| `Recover` | 지금 바로 복구 1회. `-Plan` 이면 **미리보기**(입력·생성 없음), `-Only <창 주소>` 면 그 창만, `-Batch <개수>`(기본 6) · `-DelaySec <초>`(기본 4) 로 속도 조절 |
| `Run` | 감시 루프(작업 스케줄러가 켜는 모드). `-RecentMin <분>`(기본 10, 0 이면 예전처럼 전부 복구) · `-AppGoneExitSec <초>`(기본 120) |
| `Forget` | 복구 목록에서 빼기. `-Sid <세션ID 앞 8자 이상>` 한 건, `-Stale` 옛 항목 일괄(먼저 백업) |
| `Update` | Herdr 앱 업데이트. 옵션: `-NoRestart`(파일만 교체, 창은 그대로) / `-Auto On\|Off\|Status` / `-Launcher Install\|Uninstall\|Status` |

### 10.2 목록·복구 도구 (`sessions.mjs`, Node.js)

```
node "<설치 위치>\sessions.mjs" <명령>
```

| 명령 | 하는 일 |
|---|---|
| `list [--days 14] [--limit 60] [--all]` | 세션을 표로 보기(`--all` 은 짧은/자동 세션 포함) |
| `json …` | 같은 내용을 JSON 으로(세션키퍼 창이 사용) |
| `open <세션ID 앞 6자 이상>` | Herdr 에 **새 탭**을 열어 이어서 시작. 이미 실행 중이면 거부 |
| `focus <창 주소>` | 그 창으로 화면만 이동 |
| `last` | 최근 자동 복구 결과(JSON) |
| `plan start` / `plan read` | "전부 복구" 미리보기 실행 / 읽기 |
| `recover <창 주소\|all>` | 복구 대기 작업을 키퍼로 복구(백그라운드) |
| `forget <ID>` / `forget-old` | 복구 대기에서 빼기 / 옛 항목 일괄 빼기 |
| `update-state` / `update` / `update-auto on\|off` | 앱 업데이트 상태 / 적용 / 자동 켜기·끄기 |

### 10.6 환경 변수

환경 변수는 **필수가 아닙니다.** 설치 프로그램이 이 PC 에서 위치를 찾아 설치 폴더의 `kit.env` 에 적어 두므로, 기본 환경에서는 아무것도 설정하지 않아도 됩니다. 아래 변수는 모두 **폴더·프로그램 위치나 시험용 스위치**이며, 로그인 정보 같은 비밀 값은 사용하지 않습니다.

| 이름 | 역할 | 기본값 |
|---|---|---|
| `HERDR_APP_HOME` | Herdr 설정 폴더 | `%USERPROFILE%\.config\herdr-app` |
| `KEEPER_APP_EXE` | `herdr-app.exe` 경로 | `%LOCALAPPDATA%\Programs\herdr-app\herdr-app.exe` |
| `CLAUDE_CONFIG_DIR` | Claude Code 설정 폴더 | `%APPDATA%\claude-code`(있을 때) → `%USERPROFILE%\.claude` |
| `CODEX_HOME` | Codex 데이터 폴더 | `%USERPROFILE%\.codex` 와 `.codex_runtime` 도 함께 탐색 |
| `KEEPER_APP_PROC` | (시험용) 감시할 앱 프로세스 이름 | `herdr-app` |
| `SESSIONS_KEEPER_DIR` | (시험용) `sessions.mjs` 가 키퍼 기록을 읽는 폴더 | `sessions.mjs` 가 있는 폴더 |
| `SESSIONS_NO_HERDR` · `SESSIONS_NO_CODEX` | (시험·점검용) `1` 이면 Herdr 조회 / Codex 읽기를 건너뜀 | 꺼짐 |
| `KEEPER_NO_MAIN` | (시험용) `1` 이면 키퍼가 함수만 불러오고 감시를 시작하지 않음 | 꺼짐 |
| `kit.env` 파일 | 설치가 적는 `NODE_DIR` · `HC_DIR` · `APP_EXE` · `APP_HOME` · `CLAUDE_CFG` 항목(환경 변수가 이미 있으면 그것이 우선) | 설치 때 자동 생성 |

### 10.7 빌드·시험·배포 방법 (개발자용)

일반 사용자는 이 항목이 필요 없습니다. 이 저장소를 고쳐서 다시 배포하려는 개발자를 위한 순서입니다.

```
node tests/run-all.mjs        # 1) 전체 시험(일부만: node tests/run-all.mjs codex lib)
node build-kit.mjs            # 2) 원본을 고쳤다면 설치 꾸러미(plugins\, .claude-plugin\) 다시 만들기
node build-readme.mjs         # 3) README.md / README.en.md 를 고쳤다면 HTML 다시 만들기 + md↔html·한↔영 일치 검사
# 4) 위 결과 파일까지 함께 commit → 작업 브랜치에 push → Pull Request → 병합(기본 브랜치에 직접 push 하지 않음)
```

- 시험 중 "실제 데이터" 항목(`contract`, `sessions`)은 **Claude Code·Herdr 가 설치된 PC** 의 실제 파일을 읽기 전용으로 확인하므로, 설치되지 않은 PC 에서는 통과하지 못할 수 있습니다(해당 환경 시험은 **미확인**).
- GitHub Release 는 자동으로 만들지 않습니다. 필요하면 버전 번호(`kit-src\plugin.json`, `build-kit.mjs` 의 `VERSION`)를 올린 뒤 별도로 결정합니다.

```
┌────────────────────────── 사용자 PC (Windows) ───────────────────────────┐
│  Herdr 앱 (herdr-app)  ◄── 모드: 세션키퍼 창 (main.js/model.js)           │

│        ▼                         ▼                                        │
│  herdr-core (hc) ◄───── 목록·복구 도구 (sessions.mjs + lib\*.mjs)         │

│        │ hc ls/read/send         ▼                                        │
│  ┌─────┴────────── 키퍼 본체 session-keeper.ps1 ◄── 작업 스케줄러 (1분) ──┤
│  │  · lib\appupdate.ps1 (앱 파일 교체)       watchdog.vbs                 │
│  │  · 기록: session-map.json, 로그, 심박                                   │
│  └───────────────┬──────────────────────────────────────────────────────  │
│                  ▼ 읽기 전용                                              │
│   Claude 설정 폴더(sessions·projects), Codex 데이터(~/.codex 등)           │
└───────────────────────────────────────────────────────────────────────────┘
```

| 구성요소 | 역할 | 언어 |
|---|---|---|
| 세션키퍼 창(Herdr 모드) | 화면·버튼·탭. 일은 `sessions.mjs` 에 맡김 | JavaScript |
| `sessions.mjs` + `lib\` | 세션 읽기(Claude·Codex), 창 연결, 복구 명령, 키퍼 호출 | Node.js(JavaScript) |
| `session-keeper.ps1` | 기록·복구·감시 루프·앱 업데이트 | PowerShell |
| `session-keeper-watchdog.vbs` | Herdr 가 켜져 있을 때만 키퍼를 켬 | VBScript |
| `herdr-launch.*` | (선택) 앱 시작 전 업데이트 | PowerShell + VBScript |

설계 원칙:

- **읽기 전용 우선**: 목록·상태는 읽기만 하고, 입력을 보내는 것은 안전 규칙을 모두 통과한 복구 경로뿐입니다.
- **확신 없으면 하지 않음**: 어느 대화인지 정할 수 없으면 기록하지 않고, 틀린 대화를 이어 붙이지 않습니다.
- **되돌릴 수 있게**: 바꾸기 전에 백업(`keys.json`, 바로가기, Herdr 앱 폴더, 복구 기록).
- **Herdr 는 반드시 켜진다**: 런처·업데이트가 실패해도 앱을 켭니다.
- **중복 실행 방지**: 키퍼는 Windows 잠금(mutex)으로 하나만 돌고, 앱 업데이트·복구도 각각 잠금을 씁니다.

## 15. 보안과 데이터 흐름

### 15.1 요약

| 질문 | 답 |
|---|---|
| 인터넷으로 보내나요? | **아니요.** 소스 코드(`.ps1` `.mjs` `.js` `.vbs`)에서 인터넷 접속 코드(`http`, `Invoke-WebRequest`, `fetch` 등)를 찾았으나 **없었습니다**(검색으로 확인). Herdr 앱의 새 버전은 **Herdr 자신이** 받아 두며, 이 도구는 받아 둔 파일을 옮겨 놓을 뿐입니다. |
| 관리자 권한이 필요한가요? | 아니요. 현재 사용자 범위에서만 동작합니다. |
| 비밀번호·API 키를 다루나요? | 아니요. 꾸러미 27개 파일에서 키·토큰·비밀번호·개인키·이메일 문자열을 검사해 **0건**이었습니다. |
| 대화 내용을 읽나요? | 목록 표시를 위해 Claude 대화 기록(`.jsonl`)에서 **제목·마지막 요청 일부·폴더·모델**을 읽고, Codex 는 대화 파일과 **창 화면 글자(`hc read`)** 일부를 읽습니다. 모두 **이 PC 안에서만** 처리되고 화면에 표시됩니다. |
| 입력을 보내나요? | **예, 한 가지 경우에만**: 빈 셸 창에 `claude --resume <ID>` / `codex resume <ID>` 를 입력하는 복구(안전 규칙 통과 시). 그 밖의 창에는 입력하지 않습니다. |
| 지우는 것이 있나요? | 대화 기록은 **지우지 않습니다.** 자기 폴더의 오래된 백업(최근 개수만 보관)과 임시 파일만 정리합니다. 제거 도구도 설치한 것만 지웁니다. |

### 15.2 데이터가 어디에 쓰이나

| 데이터 | 위치 | 민감도 |
|---|---|---|
| 창↔세션 기록(세션 ID·공간·탭 이름) | 설치 폴더 `session-map.json` | **중간**: 프로젝트 이름과 세션 번호가 들어 있음 |
| 로그·복구 결과 | `session-keeper.log`, `LAST-RESTORE.txt`, `restore-history.log` | 중간: 작업 폴더 이름 포함 가능 |
| 복구 미리보기 임시 파일 | `%TEMP%\session-keeper-plan.txt` | 중간 |
| 바로가기 백업 | `shortcut-backup\` | 낮음 |

> 이 파일들을 **공개 저장소·메신저·메일에 올리지 마세요.** 설치 꾸러미에는 포함되지 않습니다(빌드가 검사). 프로젝트 폴더를 저장소로 올릴 때는 이 파일들을 제외해야 합니다.

### 15.3 이 도구가 바꾸는 시스템 영역(전체 목록)

1. 설치 폴더(프로그램·기록).
2. Herdr 설정 폴더: `mods\session-keeper`, `keys.json` 한 줄(백업 생성).
3. 작업 스케줄러 작업 1개.
4. (앱 업데이트 시) Herdr **설치 폴더 안의 파일**(백업 후 교체, 실패 시 원복).
5. (런처 설치 시에만) 바탕화면·시작 메뉴 바로가기(백업 후 변경).

Claude Code 설정(`settings.json` 등)과 Codex 설정은 **건드리지 않습니다.**

### 15.4 보안상 주의할 점

- 설치·실행 스크립트는 `-ExecutionPolicy Bypass` 로 **이 스크립트 하나에 한해** 실행됩니다. 출처를 모르는 꾸러미는 실행하기 전에 `payload` 안의 스크립트를 직접 읽어 보세요.
- 같은 PC 의 다른 사용자 계정 데이터에는 접근하지 않습니다(현재 사용자 폴더만).
- 공용 PC·타인의 PC 에 설치하려면 소유자의 동의가 필요합니다([18장](#18-법률저작권라이선스상업적-용도)).

## 16. 문제·오류 대처 방법

| 증상 | 가능한 원인 | 해결 |
|---|---|---|
| `중단: Node.js 18 이상이 필요한데 찾지 못했습니다` | Node.js 미설치/구버전, 설치 직후 터미널을 안 닫음 | [4.2](#42-nodejs-받기) 설치 후 **새 터미널**에서 다시 |
| `중단: Herdr 앱(herdr-app.exe)을 찾지 못했습니다` | Herdr 미설치 또는 다른 위치 | Herdr 설치·실행 후 다시, 또는 `-HerdrApp "경로\herdr-app.exe"` |
| `중단: Herdr 설정 폴더가 없습니다` | Herdr 를 한 번도 실행하지 않음 | Herdr 를 한 번 실행한 뒤 다시, 또는 `-HerdrHome` |
| `중단: 설치 파일(payload)이 없습니다` | 압축을 풀지 않고 실행 / 폴더 일부만 복사 | 꾸러미를 **완전히 풀고**, 폴더 전체를 옮겨 다시 |
| `중단: … 이미 다른 위치에 세션키퍼가 설치되어 있습니다 … 덮어쓰지 않았습니다` | 기존 설치와 충돌 | 기존 것을 쓰거나, 교체하려면 `-Force` |
| 스크립트 실행이 막힘(실행 정책/보안 프로그램) | 회사 정책, 백신 | `install.cmd` 또는 위 `powershell -ExecutionPolicy Bypass …` 형식 사용. 정책이 막으면 관리자에게 문의 |
| 경고: 작업 등록 실패 | 작업 스케줄러 제한 | `-NoTask` 로 설치 후, Herdr 를 켠 다음 `-Mode Run` 으로 수동 실행 |
| `Ctrl+Shift+R` 이 안 열림 | 다른 기능이 그 키를 이미 사용 / 모드 로드 실패 | `Ctrl+Shift+P` → `mod.open session-keeper`. `herdr-app check "<모드 폴더>"` 로 검사 |
| 목록이 비어 있음 | 키퍼가 아직 안 켜짐 / `hc` 를 못 찾음 | 1분 기다림 → `session-keeper.alive` 확인 → `kit.env` 의 `HC_DIR` 확인 |
| 복구가 안 됨 | 안전 규칙에 걸림, 대화 기록 파일이 사라짐, 이미 실행 중 | `[미리보기]` 로 이유 확인(`건너뜀 — 이유`), `session-keeper.log` 확인 |
| "대화를 하나로 정할 수 없어 기록하지 않습니다" | 같은 폴더에 Codex 창이 둘 이상이고 화면 대조도 불확실 | 정상 동작(틀린 대화 보호). 꺼진 세션 탭에서 직접 복구 |
| 복구했는데 AI 가 하던 일이 이어지지 않음 | 복구는 **대화 기록**만 이어짐 | 정상. 하던 작업은 AI 에게 다시 요청 |
| 복구 뒤 감시·예약이 없음 | 감시(Monitor)·예약은 프로그램과 함께 사라짐 | 판정 `감시·예약 재가동 필요` 의 창에서 직접 다시 켬 |
| 앱 업데이트가 `restart` 에서 안 끝남 | 창 재시작 전 | [앱 업데이트] 두 번 클릭 또는 `-Mode Update` |
| 앱 업데이트 실패 메시지 | 파일 교체 중 오류(자동 원복됨) | `session-keeper.log` 확인 후 다시. 백업은 `herdr-app.backup-<버전>-<시각>` |
| 업데이트 뒤 창이 안 뜸 | 드문 실패 | 키퍼가 20초 뒤 대신 앱을 켭니다. 그래도 안 뜨면 시작 메뉴에서 Herdr 실행 |
| 자동 업데이트가 갑자기 "꺼짐" | 버튼을 눌렀거나 [앱 업데이트]와 겹쳐 눌림 | `-Mode Update -Auto On` |
| 글자가 깨져 보임(`?`, 이상한 글자) | 콘솔 인코딩 | 동작에는 영향 없음. 확인이 필요하면 `chcp 65001` 후 실행 |
| 키퍼가 사라졌다는 경고 | 키퍼 교체·종료 | 로그의 "같은 부팅 안에서 이전 감시가 … 사라졌습니다" — 1분 뒤 감시가 다시 켭니다. 반복되면 앞뒤 로그를 확인 |

**더 알아보려면** 먼저 볼 곳: ① 설치 폴더의 `session-keeper.log`(끝부분) ② `LAST-RESTORE.txt` ③ `-Plan` 미리보기.

**되돌리고 싶을 때**: [20장](#20-제거와-되돌리기).

## 17. FAQ (자주 묻는 질문)

<details>
<summary><b>Q1. 컴퓨터를 켜면 저절로 복구되나요?</b></summary>

아니요. **PC 부팅만으로는 아무것도 켜지지 않습니다.** Herdr 를 직접 실행하면, 약 1분 안에 키퍼가 켜지고 복구가 시작됩니다.

</details>

<details>
<summary><b>Q2. AI 가 하던 작업이 그대로 이어지나요?</b></summary>

아닙니다. **대화 기록**만 이어집니다. 꺼질 때 진행 중이던 한 번의 작업은 이어지지 않으니, AI 에게 "이어서 해 줘"라고 다시 요청해야 합니다.

</details>

<details>
<summary><b>Q3. 개인정보가 밖으로 나가나요?</b></summary>

이 도구의 코드에는 인터넷 접속 부분이 없어서 보내지 않습니다([15장](#15-보안과-데이터-흐름)). 다만 Claude Code·Codex·Herdr 자체가 하는 통신은 이 도구와 무관하며 각 서비스의 약관·설정을 따릅니다.

</details>

<details>
<summary><b>Q4. Mac 이나 Linux 에서도 되나요?</b></summary>

아니요. Windows 전용입니다(PowerShell·작업 스케줄러·Windows 프로세스 정보를 사용).

</details>

<details>
<summary><b>Q5. Herdr 안에서 설치할 수 있는 마켓플레이스인가요?</b></summary>

아니요. Herdr 에는 플러그인 설치 기능이 없습니다(`herdr-app` 명령에 모드 설치 명령이 없음을 확인). "마켓플레이스"는 **Claude Code** 용입니다. Herdr 에는 모드 폴더를 복사하는 방식으로 설치됩니다(설치 프로그램이 대신 해 줍니다).

</details>

<details>
<summary><b>Q6. 설치하면 Herdr 가 닫히나요?</b></summary>

아니요. 설치는 Herdr 를 닫지 않습니다. 앱 **업데이트를 적용**할 때만(버튼·자동) 창이 잠깐 닫혔다 열리며, 터미널은 유지됩니다.

</details>

<details>
<summary><b>Q7. Herdr 업데이트가 정말 안전한가요?</b></summary>

전체 백업 → 파일별 교체 → SHA256·버전 검증 → 틀리면 전부 원복 순서입니다. 시험용 별도 Herdr 와 개발 PC 의 실제 Herdr(터미널 26개 유지)에서 성공을 확인했습니다. 단, 모든 PC·모든 버전에서 안전하다고 **보장하지는 않습니다**([19장](#19-검증-현황과-알려진-한계)).

</details>

<details>
<summary><b>Q8. 자동 업데이트를 원하지 않아요.</b></summary>

`session-keeper.ps1 -Mode Update -Auto Off` 또는 세션키퍼 창의 **[자동 업데이트]** 버튼. 끄면 새 버전이 있어도 알림만 하고, 원할 때 **[앱 업데이트]** 로 직접 적용합니다.

</details>

<details>
<summary><b>Q9. 창을 일부러 닫았는데 다시 열리나요?</b></summary>

Herdr 가 켜져 있는 동안 직접 닫은 창은 복구 목록에서 빠지고 되살리지 않습니다. 단, 한 번에 6개 이상을 일부러 닫으면 사고로 보일 수 있어 다음에 되살아날 수 있습니다. 영영 끝낸 작업은 **[목록에서 제외]** 하세요.

</details>

<details>
<summary><b>Q10. 오래 꺼 뒀다가 켜도 되나요?</b></summary>

키퍼는 기록을 **365일** 보존합니다. 다만 **Claude Code 자체**가 오래된 대화 파일을 지울 수 있는 설정(`cleanupPeriodDays`, 기본값은 30일로 알려져 있으나 **개발 PC 에서 확인한 것은 설정이 없고 78일 전 파일이 남아 있었다는 사실뿐**)이 있어, 몇 달 꺼 둘 경우 보장하지 못합니다. 이 도구는 Claude 설정 파일을 건드리지 않습니다. 필요하면 직접 `"cleanupPeriodDays": 365` 를 설정하세요.

</details>

<details>
<summary><b>Q11. 여러 PC 에 설치해도 되나요?</b></summary>

기술적으로 PC 마다 설치하면 됩니다. 라이선스는 [18장](#18-법률저작권라이선스상업적-용도)(Apache License 2.0)을 보세요.

</details>

<details>
<summary><b>Q12. 설치를 되돌릴 수 있나요?</b></summary>

네. [20장](#20-제거와-되돌리기). `uninstall.ps1` 이 설치한 것만 지웁니다. 복구 기록은 기본으로 남깁니다.

</details>

<details>
<summary><b>Q13. 터미널에서 한글이 깨져 보여요.</b></summary>

화면 표시 문제일 뿐 동작과는 무관합니다. 스크립트는 한글 환경(UTF-8 BOM)에서 시험했습니다.

</details>

- lint / type check / build / e2e / 브라우저 시험: 이 프로젝트에는 해당 도구가 없어 **미실행**.

### 19.3 알려진 한계

- 컴퓨터가 갑자기 꺼지면 **마지막 1분 안에 시작한 세션**은 기록에 없을 수 있습니다.
- 앱 업데이트 때 **새 버전에서 빠진 옛 파일은 지워지지 않습니다.**
- Claude 의 오래된 대화 파일 자동 삭제 설정 가능성([FAQ Q10](#17-faq-자주-묻는-질문)).
- 같은 폴더에 Codex 창이 여러 개일 때 일부는 ID 가 안 보일 수 있습니다.
- 앱을 일부러 6개 이상 한꺼번에 닫으면 사고로 보일 수 있습니다.
- 세션키퍼 창의 [앱 업데이트]·[자동 업데이트] 버튼이 가까워 오조작 가능성이 있습니다.

## 20. 제거와 되돌리기

### 20.1 제거

```
powershell -NoProfile -ExecutionPolicy Bypass -File plugins\herdr-session-keeper\uninstall.ps1 [-InstallDir 경로] [-HerdrHome 경로] [-TaskName 이름] [-RemoveData]
```

| 지우는 것 | 조건 |
|---|---|
| 런처 연결 해제(바로가기 원복) | 런처를 설치했던 경우 |
| 작업 스케줄러 작업 | **이 설치를 가리킬 때만**(다른 위치를 가리키면 그대로 둠) |
| 이 설치의 키퍼 프로세스 | 항상 |
| `Ctrl+Shift+R` 연결 + `mods\session-keeper` | 모드가 **이 설치를 가리킬 때만** |
| 프로그램 파일 | 항상(복구 기록·로그는 **남김**). `-RemoveData` 면 설치 폴더 전체 삭제(설치 기록이 있을 때만) |

Herdr 앱·터미널·다른 모드·Claude/Codex 대화 기록은 건드리지 않습니다.

### 20.2 부분적으로 되돌리기

| 되돌릴 것 | 방법 |
|---|---|
| 자동 실행만 | `schtasks /Delete /TN "HerdrSessionKeeper-Watchdog" /F` |
| 앱 자동 업데이트 | `session-keeper.ps1 -Mode Update -Auto Off` |
| 바로가기 | `session-keeper.ps1 -Mode Update -Launcher Uninstall` (백업 `shortcut-backup\`) |
| `keys.json` | 백업 `keys.json.bak-before-session-keeper-kit` 을 `keys.json` 으로 복사 |
| 복구 목록에서 뺀 항목 | 백업 `session-map.json.before-forget-old-<시각>` 을 `session-map.json` 으로 복사 |
| Herdr 앱 업데이트 | `herdr-app.backup-<버전>-<시각>` 폴더의 파일로 되돌림(Herdr 를 닫은 뒤) |
| 프로그램 업데이트 | 설치 폴더 `_backup\<시각>\` 에서 파일 복사 |
